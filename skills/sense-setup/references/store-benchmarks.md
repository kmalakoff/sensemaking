# Store performance trade-offs

Release `0.28.0`, 2026-10-12: Apple M4 Pro, Node v26.11.1, the same 6,566-note tree.

Times are relative to SQLite (1.00×); lower means less elapsed time. Index time excludes embeddings. Search includes CLI startup and each store's selected work, not isolated engine speed.

| Store | Index time | Lexical time | Semantic time | Semantic nDCG@10 |
|---|---|---|---|---|
| sqlite | 1.00× | 1.00× | 1.00× | 0.3306 |
| duckdb | 1.52× | 1.43× | 1.19× | 0.3283 |
| turso | 1.63× | 1.11× | 1.50× | 0.3299 |

Relevance uses the same NFCorpus queries, judgments and model; higher nDCG is better. Small differences are not a reason to switch stores. Choose capabilities and SQL compatibility first; check a representative workload if latency matters.

[Full measurements and methodology](https://github.com/kmalakoff/sensemaking/blob/master/benchmark/reports/2026-10-12-0.28.0-release-gate.md). Generated by `node benchmark/report.ts --release <version>`; these results describe this run, not a permanent engine ranking.
