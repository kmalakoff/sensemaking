### 2026-08-30: 0.19.0 release gate (turso store, parse-once reconcile)

Full battery, `node benchmark/release.mjs` (compare + 13k/26k scale + stress + both quality
evals), Apple Silicon (M4 Pro, 14 logical cores), Node 26.7.0, still on 0.18.4's number per
RELEASING.md step 2; the 0.19.0 bump happens after this sitting. Default store (sqlite)
throughout, matching every prior gate's scope.

**Provenance.** This report is assembled from two invocations of the same battery on the same
tree, not one continuous run: the first invocation's `fever` stage was lost when its shell died
before the stage finished, so `fever` was re-run separately afterward. Every other stage (compare,
13k scale, 26k scale, stress, nfcorpus) is a single invocation from the first run. The code under
test was identical across both invocations; nothing changed in the tree between them.

The release's two headline changes, per CHANGELOG.md's 0.19.0 entry: `turso` joins `sqlite` and
`duckdb` as a store option, and reconcile now hands the chunk text it already parsed forward to
the embed pass instead of re-parsing the file a second time (a WeakMap handoff, `src/embed/handoff.ts`).
`release.mjs` has no `--version` canary step, so that row is not part of this sitting; it is
carried forward unchanged in BENCHMARKING.md's numbers-of-record table.

#### Limitation: the release comparison never crosses the embed path

`compare.mjs` builds its corpora with `embed: false` (`benchmark/lib/corpus.mjs:139`), so the
hub before/after table above never exercises the embed or vector path: `embedPending` never
runs. This release's parse-once change (chunk text handed forward from reconcile to the embed
pass instead of being re-parsed) lives entirely on that path, so it has no before/after number
in this report. Its correctness is covered elsewhere (the per-store `vectors.test.ts` suites,
`test/integration/embed.test.ts`, the store-parity vector cases, and the two handoff specs that
each fail for their own reason when one path is deliberately broken); only the timing comparison
is missing. This gap is tracked as item 3.6 in `plans/PLAN.md`. A reader should not infer from
this report that the parse-once change was measured and found to cost nothing: it was not
measured here at all.
